## Decisions agreed with the user (2026-10-12)

- store `compiled_code` and `relation_name` per node result
- no copy-after-run archive: isolated per-run folders straight away
- `LOG_ROOT_LOCATION` (`--log-root-location` / `LOG_ROOT_LOCATION` /
  `DBTX_LOG_ROOT_LOCATION`), required in platform mode (exit 2, like DB_URI); the
  example and template configs set `LOG_ROOT_LOCATION=.dbtx/logs`
- layout `<project_name>/<date>/<floored_hour>/<job_id>/`
- every platform invocation has a unique job id (given or generated), retries included;
  an existing folder → exit 2 (duplicates only caught within the hour: accepted for
  now)
- dbt gets the job id as `DBT_ENV_CUSTOM_ENV_DBTX_JOB_ID`; the recorder takes it from
  dbtx's config; `read_job_id` falls back to `DBTX_JOB_ID`; `DBTX_JOB_ID` in `--vars` →
  exit 2 in platform mode, allowed in standalone
- standalone mode: `--log-root-location` (and so run folders) rejected
- `dbtx warm-cache`: warms the partial-parse cache in the project's own target folder
  without running anything; real runs copy it into their folder; run outputs are not
  copied back
- docs site = `<dbt_project>/<target>`; `--docs-loc` defaults to it in platform mode
  (install / status / serve); `docs patch` from the CLI keeps explicit parameters
- platform runs that execute nodes copy their `reports/` into the docs site and patch it
  internally (the run commands orchestrate; patch stays a utility)
- after `dbtx docs generate` the user runs `dbtx docs install`
  (`docs/flows/docs_refresh.md`); generate copies `index.html`, `manifest.json`,
  `catalog.json` into the docs site (the page loads the JSON files beside it)

## Decisions made during implementation

- **Folder name fallback:** the project folder's name when dbt_project.yml has no usable name.
- **`--job-id` elsewhere is an error**, and `DBTX_JOB_ID` in `--vars` is refused for every dbt command in platform mode.
- **Run folders do not depend on the database:** `LOG_ROOT_LOCATION` is required with `DB_BACKEND=disabled` too.
- **The project target folder** (`DbtxConfig.project_target_dir`) is resolved in `load_config` as dbt would (`DBT_TARGET_PATH`, `target-path`, `target`).
- **dbt's metadata cache** is reset around every job id.

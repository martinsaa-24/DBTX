## Decisions made during implementation

- **Registry:** an entry point named like a built-in backend is ignored (a plugin cannot replace SQLite or Postgres). Plugins are listed by name without loading, and loaded only when a URI asks for their backend, so a broken plugin never affects the built-ins. A plugin that fails to import, is not a `StoreAdapter` subclass, or whose `dialect` differs from its entry-point name is a `StoreError` (a `ConfigError` in `load_config`).
- **Driver rules moved onto the adapter classes** (`driver`, `driver_package`, `driver_hint`, `install_hint`, `display_name`), so `config.validate_db_uri` has no per-backend branches and plugins get the same checks. Messages for SQLite and Postgres are unchanged.
- **`DB_SCHEMA` names** must match `[a-z_][a-z0-9_]{0,62}`: what Postgres accepts unquoted, so the configured name is exactly the name in the database (no case folding or quoting surprises).
- **`upsert` refuses `least` / `greatest` on nullable columns:** SQLite's `max(a, NULL)` is NULL, Postgres' `greatest(a, NULL)` is `a`. Every column the plan merges this way is NOT NULL, so refusing is simpler than papering over the difference. It also refuses the same key twice in one call (Postgres raises "cannot affect row a second time", SQLite would apply both rows), and `keys` other than the primary key (the only unique constraints in the spec).
- **The G2 refusal adds a hint** to the plan's message: "If the project moved, run `dbtx db projects rebind <name> --folder <folder>`".
- **`rebind` also refuses a new folder that is not a project folder** (no `dbt_project.yml` under the platform root), unless `--force`: a typo would otherwise hand the name to a folder that does not exist. The plan only names the old-folder check.
- **`dbtx db projects` always uses the database** (no enforcement switch), and is in the "uses the database" command class, so under enforcement a missing `DB_URI` fails in `load_config` like any other database command.
- **Rebind records the new owner:** `claimed_at` and `claimed_by_host` are reset to the rebind's time and host; `last_seen_at` is kept (it is about runs, not ownership).
- **`greatest` / `least` carry the first value's type** (`type_=`), so a timestamp result goes through `UTCDateTime` and comes back aware UTC on both backends.
- **`DB_SCHEMA` with SQLite** is an error only when set through a layer (the default `dbtx` is not "setting it"), and, like a malformed `DB_URI`, even when the backend is disabled. Without a `DB_URI` the schema cannot be checked against a backend and is accepted.

- **The Phase 1 `engine` fixture is kept** for the column-type and model tests instead of being replaced by `store` (the Phase 1 note suggested replacing it). What those tests prove (UTC normalisation, CHECKs, relationships) must hold on a bare connection; the adapter sets UTC on every connection, which would hide a type that relies on it. Every adapter test uses `store`, as the plan's "done when" asks.

- **The database start-up checks for dbt commands run only once `ENFORCE_DB_REQUIREMENTS` is on (plan Phase 5).** Nothing is recorded before Phase 5, and nothing can create the tables before Phase 3 (`dbtx db init`), so connecting, checking the tables and claiming a name for every `dbtx build` now would only add failures. The checks are complete and tested (with the `enforce` fixture); Phase 5's flip turns them on together with the other database-motivated failures. `dbtx db projects` (step 10) uses the database whatever the switch says, because that is its whole job.
- **G1 for the current project is decided at start-up, not in `load_config`** (needed for "established owner wins"). While not enforced it is still a warning from `load_config`, as before.
